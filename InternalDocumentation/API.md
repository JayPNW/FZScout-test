The json you send is going to be really simple:

The request header would be
POST https://fangbreaker.zone/api/client/bonuses
Content-Type: application/json
X-API-Key: fz_live_...


API keys would still need to be generated by the user on the site, the same way they would for the existing pasrer (which is admittedly totally abandoned due to complete lack of user interest in the eq scene, and my not caring to fix memory issues for something literally nobody uses)

the JSON body is:

```
{
    "serverName": "Fangbreaker",
    "zoneName": "The parsed zone name",
    "bonusKey": "item-exp"
}
```

The public endpoints you can use to get bonus / zone data are:
GET https://fangbreaker.zone/api/servers/fangbreaker/bonuses/types
GET https://fangbreaker.zone/api/servers/fangbreaker/bonuses/zones

and
GET https://frostreaver.zone/api/servers/frostreaver/bonuses/types
GET https://frostreaver.zone/api/servers/frostreaver/bonuses/zones

for fangbreaker and frostreaver respectively.

Today's bonus for every zone (not in the original notes; found by trying it):
GET https://fangbreaker.zone/api/servers/fangbreaker/bonuses/today

Each entry has the zone's `name` and its `bonus`: a bonus key, `none`, or `unconfirmed` when nobody has reported it today.

obviously load the types from the appropriate endpoint instead of hard-coding them.

The 200 OK response should look like:
```
{
    "ok": true,
    "data": {
        "updated": true,
        "zoneBonus": {}
    }
}
```

400 is an error for invalid payload
401 is missing/invalid api  key
403 is a banned/timedout account
404 is the zone or server was not found
500 is a server-side failure

Duplicate submissions will return the same thing, and duplicate submissions are harmless. The backend will disregard them unless it's a change.

The POST endpoint doesn't need a date, it's uses America/Los_Angeles per server configuration.

The API key itself will tie submissions to the user and any timeouts or bans or whatever are respected. Basically a submission through the API is the same as a user trying to login and submit it on the web gui.
